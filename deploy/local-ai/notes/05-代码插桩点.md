**怎么写**（贴合仓库风格）：

在 `config.py` 里加（复用已有的秒数解析器 `config.py:1130-1138 _seconds`）：

```python
DEFAULT_JUDGE_TIMEOUT = 5.0

def judge_timeout_from_env() -> float:
    """`JUDGE_TIMEOUT`：判断模型一次请求最多等多少秒。本地模型比云端慢，需要放宽。"""
    value = (os.environ.get("JUDGE_TIMEOUT") or "").strip()
```

```python
def judge_timeout() -> httpx.Timeout:
```

## 方案 A：shim（零改码，推荐先做）

需要 `.env`：

```sh
JUDGE_PROVIDER=jev
JEV_BASE_URL=http://127.0.0.1:8097/v1
JEV_API_KEY=local
JEV_MODEL=local-judge
```

shim 代码在 `F:\local-ai\judge_shim.py`（已验证）。它做的事：

1. 收 `POST /systemone`，body `{"model","state","questions"}`
2. `schema_for(questions)` 按 `type` 生成 strict JSON Schema：
   - `noul` → `{"type":"object","properties":{"noul":{"type":"number"}},"required":["noul"],"additionalProperties":false}`
   - `score` → `{"probabilities":{"0":..,"1":..,...}}`（级数 = `len(criteria)`）
   - `choice` → `{"probabilities":{选项中文名:..}}`（键 = `criteria.keys()`）
   - 顶层 `required` = 全部问题键，`additionalProperties:false`
3. `prompt_for(state, questions)`：`json.dumps(state, ensure_ascii=False, indent=1)` 嵌进去 + 逐题列 instructions 与 criteria
4. 打 `{UPSTREAM}/chat/completions`，`response_format: json_schema`、`temperature: 0`、`max_tokens: 700`
5. 读 `choices[0].message.content` 当 JSON，返回 `{"answers": <它>, "usage": {"input_tokens": usage.prompt_tokens}}`

### 要注意的细节（都踩过）

- **`JEV_API_KEY` 必须非空**，`_required("JEV_API_KEY")` 会检查
- **`JEV_MODEL` 必须等于 llama-server preset 的段名**（`local-judge`），因为 eidolon 把模型名原样传给 shim，shim 再原样传给 llama-server
- 阈值族：`judge_family("local-judge")` → `None` → 套 jev 阈值 + 警告。要精确就得跑 `uv run eidolon eval judge --only retrieval` 重新标定（399 个用例）
- `check_judge()` **不会**在启动时试 Jev（只有 Cloudflare/百炼会），所以 shim 没起也能启动，第一次回合才报错。想早点发现就手动 `curl -X POST http://127.0.0.1:8097/systemone -d '{"model":"local-judge","state":{},"questions":{"check":{"type":"noul","instructions":"这是一条测试消息吗？"}}}'`
- `try_judge_model()`（后台保存时用）对非 Cloudflare/百炼走 `ask({"测试":"保存前试调"}, {"check": _CHECK_QUESTION})` → 也走 shim，能验
