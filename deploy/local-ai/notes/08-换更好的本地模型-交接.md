## 为什么要换

`JUDGE_PROVIDER=local` 的判断模型目前是
`gguf/qwen3-4b-instruct-2507-q4_k_m.gguf`（2 497 281 120 B），在 `models.ini` 的
`[local-judge]` 段。2026-11-10 实测 `eidolon eval judge --provider local --only retrieval`
（47 例）：

- 整体准确率 **65.96%**（短例 43 条 62.8%，4 个长例 100%）。
- 分类型：`recall`（剧情回顾）几乎全对、`references`（查资料）约一半、
  **`memories`（要不要检索记忆）几乎全错** —— 该查记忆的话被判成「不检索」。
- 失败机制：`about_producer` 概率系统性偏低，且阈值仍套 jev 族
  `0.5/0.5/0.5/0.5/0.7/0.4/0.5`（`judge_thresholds_for("local-judge")` 落到 jev 并打警告）。
  **有可能不全是模型能力问题，而是阈值错配**，换模型前应先想清楚这点（见「下一步」）。
- 单请求 663–698 token 约 1.5–3.7 s；长例 2831–3154 token 10.4–12.8 s，都在
  `.env` 的 `JUDGE_TIMEOUT=30` 内。

基线 JSON 曾写到 `%TEMP%\eval-judge-local.json`（临时目录，重启后可能没了；要留档请重跑
`--json` 指定仓库外路径）。完整结论见
[`.scratch/local-ai/issues/02-local-rerank-timeout.md`](../../../.scratch/local-ai/issues/02-local-rerank-timeout.md)
的「本地化效果实测」。

## 工具坑（每次都会踩，务必复用）

- **`uv run` 会把 `backend/uv.lock` 刷成阿里云镜像重写**（`revision = 3`→`5`、
  `https://mirrors.aliyun.com/pypi/simple/`、2157+/2157-），与任务无关，
  提交前必须 `git checkout -- backend/uv.lock`。
- **pyright 必须在 `backend/` 下用 `uv run pyright`**（`scripts/affected-tests.sh:68` 的跑法），
  仓库根直接 `python -m pyright` 会误报
  `backend/src/eidolon/rerank.py:13:8 - error: Import "httpx" could not be resolved (reportMissingImports)`。
- **GBK 控制台**：`eidolon doctor` 打印 `✓` 会报
  `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713' in position 78`，
  跑前设 `$env:PYTHONIOENCODING='utf-8'`。
- **`.ps1` 必须存成 UTF-8 with BOM**（PS 5.1 无 BOM 按 GBK 解码咬坏中文）；`write`/`edit`
  工具改完会掉 BOM，用 pwsh
  `WriteAllText($p, $t, [System.Text.UTF8Encoding]::new($true))` 补回。
- **`.env.example` 曾被 ops 当凭据拒读**（`rejected: CREDENTIAL_DENIED`），须走 shell 脚本改写。
- **删文件前先看 `git ls-files`**：曾误删 8 个已跟踪的 `.pyc`（`__pycache__/` 规则加得晚），
  用 `git checkout --` 才恢复；ignore 规则对已跟踪文件不生效。
- 提交信息风格：`type(scope): 中文描述` + 正文；提交信息可写仓库根
  `.commit-msg-tmp.txt` 再 `git commit -F`，用完即删（`.git\` 下在受限沙箱里写不进）。
