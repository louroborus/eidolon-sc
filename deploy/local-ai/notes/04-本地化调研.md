## 1. 向量化 + 重排：零改码，已验证

eidolon 的 embedding 和 rerank **共用同一个 `SILICONFLOW_BASE_URL`**：

- `backend/src/eidolon/embedding.py:116` `self._url = base_url.rstrip("/") + "/embeddings"`
- `backend/src/eidolon/rerank.py:99` `self._url = base_url.rstrip("/") + "/rerank"`
- `config.py:873` 与 `config.py:930` 都读 `os.environ.get("SILICONFLOW_BASE_URL")`

所以只要一个服务同时提供 `/v1/embeddings` 和 `/v1/rerank`，两项一起切过去。

### llama-server router 模式（一个进程、一个端口、两个端点）

`F:\local-ai\models.ini`（内容见该文件）：

```ini
[Qwen/Qwen3-Embedding-0.6B]
model = F:/local-ai/gguf/qwen3-embed-0.6b-q8_0.gguf
embeddings = 1
pooling = last
ctx-size = 8192
n-gpu-layers = 99

[Qwen/Qwen3-Reranker-0.6B]
model = F:/local-ai/gguf/qwen3-reranker-0.6b-q8_0.gguf
reranking = 1
ctx-size = 8192
n-gpu-layers = 99
```

```powershell
F:\local-ai\bin\llama-server\llama-server.exe --models-preset F:\local-ai\models.ini --port 8094 --host 127.0.0.1
```

- `GET /v1/models` 会列出两条，`status.value = "unloaded"`（**按需加载，正常**）
- **INI 的 `[名字]` 必须与 eidolon 的 `EMBEDDING_MODEL` / `RERANK_MODEL` 完全一致** —— eidolon 把模型名原样放进请求体做路由
- 相关参数：`--models-dir PATH`、`--models-preset PATH`、`--models-max N`（默认 4）、`--models-autoload`

### 需要的 `.env` 四行

```sh
SILICONFLOW_BASE_URL=http://127.0.0.1:8094/v1
SILICONFLOW_API_KEY=fake        # 必须非空！config.py:925 为空会让 RerankSettings.from_env() 返回 None
EMBEDDING_MODEL=Qwen/Qwen3-Embedding-0.6B
RERANK_MODEL=Qwen/Qwen3-Reranker-0.6B
```

### 实测验证（用 eidolon 自己的客户端类，不是手搓请求）

探针脚本实例化 `SiliconFlowEmbedder` / `SiliconFlowReranker` 打本地 8094：

```
embed_documents -> 4 条, 维度 1024
  全是零？ False
embed_query  -> 维度 1024
rerank ->
  0.975386  idx=0  制作人说想去海边
  0.944441  idx=3  海边很漂亮，一起去吧
  0.000361  idx=1  今天工作很累，想早点睡
  0.000078  idx=2  明天要早起开会
thresholds -> RerankThresholds(references=0.3, memories=0.01)
```

**语义正确，而且 `thresholds_for()` 按模型名命中了 `KNOWN_THRESHOLDS` 里的 `Qwen/Qwen3-Reranker-0.6B`（0.3/0.01）→ 不用重新标定阈值。**

### 注意事项

- `embedding.py:26` `_QUERY_INSTRUCTION = "Instruct: 根据问题，检索相关的剧情台词\nQuery: "` 是 **Qwen3 专用硬编码**，只加在 query 上（`:129`），文档不加 → **换 embedding 模型必须仍是 Qwen3 系列**，或改这行 + 跑 `eidolon reembed`
- 换模型/维度后要 `uv run eidolon reembed`（用库里原文重新向量化，不重下剧情）
- embedding 请求体带 `encoding_format: "float"`，llama-server 能接受（实测）
- rerank 请求体带 `return_documents: False`，llama-server 也能接受（实测）

## 2. 判断模型：能本地化，但要一个 shim（或新 provider）

### 为什么不能零改码

`JEV_BASE_URL` 可以指向任何服务，但 eidolon 期望的是 **TypeSafe System One 协议**：`POST {base_url}/systemone`，body `{"model","state","questions"}`，响应 `{"answers": {key: dict}}`。llama-server 只有 `/v1/chat/completions`，协议对不上。

### 已验证的方案：`F:\local-ai\judge_shim.py`

把 `/systemone` 翻译成 `/v1/chat/completions`：

- 按 `questions` 里的 `type` 生成 **strict JSON Schema**（`noul` → `{"noul": number}`；`score` → `{"probabilities": {"0".."N-1": number}}`；`choice` → `{"probabilities": {选项中文名: number}}`）
- 用 `response_format: {"type":"json_schema", ...}` 让 llama-server 强制输出合法 JSON —— **llama-server 支持**，实测中文键正确
- `temperature: 0`，`max_tokens: 700`
- 上游响应的 `usage.prompt_tokens` 填进 `usage.input_tokens`

### `.env`

```sh
JUDGE_PROVIDER=jev            # 默认值，可不填
JEV_BASE_URL=http://127.0.0.1:8097/v1
JEV_API_KEY=local             # 必须非空，_required 会检查
JEV_MODEL=local-judge         # 必须与 llama-server preset 的段名一致
```

### 实测：用 eidolon 自己的 `JevJudge` 类打 shim，三种题型全通

```
# 检索三问（judge_questions()）
{"needs_retrieval": {"noul": 0.3}, "recall": {"noul": 0.1}, "about_producer": {"noul": 0.0}}

# 好感度 + 照片（affinity_judge.QUESTIONS + photo_judge.QUESTIONS）
{"affinity": {"probabilities": {"0": 0.0, "1": 0.1, "2": 0.6, "3": 0.2, "4": 0.1}},
 "out_of_line": {"noul": 0.0}, "manipulation": {"noul": 0.0}, "photo": {"noul": 0.0}}

# 情绪 + 点头（emotion._EMOTION_QUESTION + _NOD_QUESTION）
{"emotion": {"probabilities": {"平静": 0.6, "开心": 0.2, "害羞": 0.1, "惊讶": 0.05,
                               "难过": 0.03, "生气": 0.01, "思考": 0.01}},
 "nod": {"probabilities": {"同意": 0.8, "否定": 0.1, "都不是": 0.1}}}
```

形状与 `judge.py:214 _reply()` 的校验（`dict[str, dict]`）完全对得上。

### 延迟实测（AMD RX 6750 XT / Vulkan）

| 请求 | 冷 | 热 |
|---|---|---|
| 3 个 noul（114 prompt / 40 completion tokens） | 0.98 s | 0.51 / 0.53 / 0.53 s（`cached_tokens: 113`） |
| 8 问题（6 noul + score + choice；206 / 189 tokens） | 3.56 s | 2.64 / 2.66 s（`cached_tokens: 205`） |

`JUDGE_TIMEOUT = 5 s`（`judge.py:207` 硬编码）。2.6 s 落在里面，但：
- **冷启动**（模型首次加载进显存）会超
- **长上文**（`JUDGE_HISTORY = 4` 条消息 + `_SCENE` 前缀 + 5 档描述）会超

→ 想让本地 judge 稳，**必须把超时做成可配**，见 `05-代码插桩点.md`。

### 阈值问题（重要）

`judge_family(model)` 按模型名认族：`clef`/`clef-flash`/`jev`/`jev-*`/`decision-model`/`decision-model-*`，**其他一律 `None`** → 套 `FALLBACK_FAMILY = "jev"` 的阈值（0.5/0.5/0.5/0.5/0.7/0.4/0.5）并打印警告：

```
judge model local-judge has no thresholds of its own; it judges by jev's: ...
```

可选做法：
- 忍这个警告，用 jev 阈值（最省事，但本地 4B 的概率分布和 Jev 不一样）
- 把模型命名成 `xxx/jev-something` 骗过 `judge_family`（不诚实，不建议）
- 跑 `uv run eidolon eval judge --provider jev --only retrieval` 对着 `backend/eval/judge.toml` 的 **399 个用例**重新标定，再在 `judge.py:98 JUDGE_THRESHOLDS` 加一族

## 3. 为什么 Ollama / llama-cpp-python / 官方 llama.cpp 都不合适

### Ollama：**没有 rerank 端点**

拉 `https://raw.githubusercontent.com/ollama/ollama/main/docs/api.md` 逐条核对，端点只有：Generate a completion / Generate a chat completion / Create a Model / Check if a Blob Exists / Push a Blob / List Local Models / Show Model Information / Copy / Delete / Pull / Push / **Generate Embeddings（`POST /api/embed`）** / List Running Models / Generate Embedding（`/api/embeddings`，已废弃）/ Version。

**全文没有任何 rerank。** 而 eidolon 的 embedding 和 rerank 共用同一个 `SILICONFLOW_BASE_URL` → 用 Ollama 直接缺一半功能。

### llama-cpp-python：也没有 rerank

`llama_cpp/server/app.py` 只有 `"/v1/embeddings"`（第 361 行），无 rerank 路由。PyPI 最新 0.3.36，**没有 Windows 预编译 wheel**。

### 官方 llama.cpp release：下载不动

`llama-b12074-bin-win-vulkan-x64.zip`（35.8 MB）HTTP 206 能连，但约 **1 MB/min**（2 分钟只到 2 MB）。镜像 `ghfast.top` → 403，`ghproxy.net` → 000。

### 所以用的是 LM Studio 残留的 llama.cpp

LM Studio 卸载后 `~/.lmstudio/extensions/backends/llama.cpp-win-x86_64-vulkan-avx2-2.36.0/`（49 MB）仍能独立运行，已整目录搬到 `F:\local-ai\bin\llama-server\`，`--version` / `--list-devices` / 实际起服务全部验证通过。**不依赖 LM Studio，也不需要装 Ollama。**

（顺带：LM Studio 这类管理工具本身**没必要**——它唯一的价值就是附带这套 llama.cpp。模型下载 ModelScope 更快，服务管理一条命令行就够。）

## 5. 为什么 TTS / STT 现在做不了

### TTS：只有 Fish，地址写死三处

- `backend/src/eidolon/call.py:797` `FISH_TTS_URL = "wss://api.fish.audio/v1/tts/live"`
- `backend/src/eidolon/greetings.py:45` `FISH_TTS_HTTP_URL = "https://api.fish.audio/v1/tts"`
- `backend/.venv/Lib/site-packages/pipecat/services/fish/tts.py:203` `self._base_url = "wss://api.fish.audio/v1/tts/live"`（`grep environ|getenv` 无命中）

**全仓没有 `FISH_AUDIO_BASE_URL`。** 实现是 `call.py:413` `class FishTTS(InterruptsFirst, ProxiedWebsocket, FishAudioTTSService)`，来自 pipecat。

要本地化必须：
1. 写新的 `TTSService` 子类（pipecat 自带 `kokoro` / `piper` / `pocket_tts` / `xtts` 可直接用，缺的只是可选依赖 + 模型文件）
2. 改 `call.py:721 def tts(...)` 工厂
3. 加 VAD —— `call.py:1277-1282` 的 `TransportParams(audio_in_enabled=True, audio_out_enabled=True, audio_out_sample_rate=sample_rate)` **没有 `vad_analyzer`**，而 `pipecat/stt_service.py:798-806 SegmentedSTTService` 的 docstring 明写 "Requires VAD to be enabled in the pipeline to function properly"
4. `FishAudioModel` 这个 `Literal` 波及后端 12 个文件：`account_api.py app.py call.py config.py delivery_cues.py engine.py greetings.py own_keys.py read_aloud.py reply_format.py admin_config_api.py`，还要改前端 `OwnKeysSettings.tsx`、`AdminConfig.tsx`、`api.ts:9`、`zh.ts:854-856`、`localOwnKeys.ts`
5. `readings.py` 的读音表机制会失效（每个 Fish 请求都带 `pronunciation_dictionary`，OpenJTalk romaji + 音高数字如 `ha0shi1ga0`）
6. `CallMeter` / `Origin` / activity 记账都写死了 Fish URL

### STT：`STT_PROVIDER` 只有两个值

- `config.py:40` `SttProvider = Literal["soniox", "bailian"]`
- `call.py:700 def stt(...)`：bailian → `BailianSTTService`，否则 `ProxiedSoniox`
- pipecat 自带 `whisper`（需 `faster_whisper`）和 `funasr`（需 `funasr`），**但项目 venv 里两个都没装**
- AMD 无 CUDA → faster-whisper 只能 CPU 或 DirectML

### 如果将来铁了心要做

最小路径：`faster-whisper`（CPU，small/base 够用）+ Kokoro ONNX（CPU，或 DirectML）。两个都要从 PyPI 装（可达），模型从 ModelScope 下（可达）。工作量约等于一张独立的大票，涉及前后端 + 三语文档 + 12 个后端文件的 `FishAudioModel` 类型。
