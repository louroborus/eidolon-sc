## 工具链陷阱（踩过的，别再踩）

### 1. uv 默认缓存目录被拒

```
error: Failed to initialize cache at C:\Users\<user>\AppData\Local\uv\cache
cause: failed to open file ...\sdists-v9\.git: 拒绝访问。(os error 5)
```
**解法**：`$env:UV_CACHE_DIR="$env:TEMP\eidolon-uv-cache"`

### 2. pyright 满屏 import 错 = 权限问题，不是代码坏

受限沙箱下 pyright 读不到 `backend/.venv/Lib/site-packages`，报 500 条 `Import "pytest"/"fastapi"/"uvicorn"/"pipecat..." could not be resolved (reportMissingImports)` + `Variable not allowed in type expression`。
放权后 `uv run pyright` 直接 0 errors。**先怀疑权限。**

### 3. `sh` 不在 PATH，bash 要全路径

```powershell
& "C:\Program Files\Git\bin\bash.exe" -c "cd /f/eidolon-sc && sh scripts/check-scratch.sh"
# 或直接
& "C:\Program Files\Git\bin\bash.exe" scripts/check-discipline.sh
```
MSYS 的 `sh.exe` 直接跑会 `fatal error - couldn't create signal pipe, Win32 error 5`（沙箱挡命名管道）。
`files` 里写 `/f/eidolon-sc` 而不是 `F:\eidolon-sc`。

### 4. 日志绝对不能写进仓库

`.tmp-ruff.log`、`.dsh-logs/` 写进 `F:\eidolon-sc` 会污染工作区。
**一律写 `%TEMP%\eidolon-check\`**，用完删。

### 5. `uv run` 在后端正跑着时可能失败

因为要同步虚拟环境、`eidolon.exe` 被占。→ 先停后端，或加 `--no-sync`。

### 6. `Get-CimInstance` 在受限沙箱下 CIM access denied

用 `Get-WmiObject`（旧接口）或 `netstat -ano` + `Get-Process` 替代。放权后 `Get-CimInstance Win32_Process` 可用（能拿 CommandLine 和 CreationDate）。

### 7. pytest cache / `__pycache__` 会破坏「干净工作区」

跑完测试要删：`backend/.pytest_cache`、`backend/src/eidolon/**/__pycache__`、`backend/tests/__pycache__`、`frontend/tsconfig.tsbuildinfo`。
